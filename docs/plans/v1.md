# v1 — Proof of Concept

Goal: a working task-tree overlay proving the core interaction loop is fast, low-memory,
and pleasant, on X11/GNOME. Full approved plan: the root design doc that seeded this repo.

## Scope (in)
- Resident process; two global hotkeys (toggle full overlay, quick-add box), configurable.
- Borderless, transparent, always-on-top overlay covering the primary monitor; fast
  show/hide; semi-transparent scrim; quick-add centred box with drop shadow.
- Task model + forest (ordered children); standalone task creation on Enter.
- Tidy-tree layout: variable node heights, shared per-layer y, parents centred, no overlap,
  multi-tree forest.
- Rounded-rect nodes + border + wrapped height-to-fit text; curved/straight bezier edges.
- Drag & drop reparent with reflow/gap-opening, insertion index, preview edge, cycle
  prevention; **snap** on drop (no animation).
- Single-line UTF-8 text input (caret, editing keys, clipboard paste).
- JSON persistence + TOML config at XDG paths.
- On-demand render loop (~0 idle CPU).
- `IPlatform` + `IClassifier` seams; `NullClassifier` active (LLM off by default).

## Scope (out — see FUTURE.md)
Animation/tweening, true superellipse, link highlighting + browser redirect, node text
editing, collapse/expand, undo/redo, multi-select, Wayland, multi-monitor, live LLM.

## Verification
- Automated: `ctest` — `core_tests` (layout invariants, forest reparent/cycle) and
  `store_tests` (persistence round-trip, config, hotkey parsing). Both green.
- Manual: build, run resident (~0% CPU), toggle overlay while another app is focused,
  quick-add a task, drag to reparent (observe reflow + snap), reject descendant drop,
  restart to confirm persistence, edit config and confirm it applies.

- Global hotkeys under GNOME/mutter are the main runtime risk (Spike 0 in the root plan).
  The app already warns about chords it fails to grab.
